# Bug 分类与关系

> 项目级口径说明，不是逐条流水账。逐条记录见 [`bug-record.md`](bug-record.md)，
> 检索入口见 [`bug-index.md`](bug-index.md)。

## 1. 层级分类

| 层级 | 含义 | 本项目典型位置 |
|---|---|---|
| `frontend` | 页面渲染、组件、交互 | `web/src/**` |
| `backend` | 业务逻辑、引擎、接口 | `server/app/**` |
| `db` | 表结构、迁移、ORM | `server/app/models/`、`server/migrations/` |
| `integration` | 前后端契约、SSE、真实链路 | `verify_t702` / UI e2e |
| `test` | **验证脚本自身**的缺陷 | `scripts/test-script/**`、`.workbuddy/verify/**` |
| `deploy` | 启动、端口、环境 | `core/lifecycle.py`、启动脚本 |

> 🔑 **`test` 层级必须单列**。本项目已两次栽在「测试全绿但测的不是真东西」：
> T-706（断言把缺陷固化成了期望）、Bug-003（子进程没起来、A1 却假通过）。
> 看到「产品明明没问题/明明有问题而测试全绿」，先怀疑这一层。

## 2. 根因分类

| 类别 | 含义 | 本项目已见实例 |
|---|---|---|
| 测试断言漂移 | 功能/数据增补后，断言未同步 | Bug-004、Bug-002 |
| 测试环境隔离 | 脚本依赖的外部状态（端口、进程、数据）未隔离 | Bug-003 |
| 文案泄漏 | 内部术语/实现名进入用户界面 | Bug-001 |
| 状态同步 / 时序 | 异步状态、竞态 | T-702（取消后界面停在「正在取消」） |
| 契约不一致 | 前后端字段/语义不一致 | T-706（倍数不校验、取消响应体） |
| **反查口径漂移** | **写入侧改名 / 换形后，读取侧仍按原形精确比对 → 静默失配** | **Bug-006**（`X` → `X_1` 后 stem 反查全失效）；同族见 T-719 复盘 |
| **消费侧接线缺失** | **能力/结果已产出并落库，但没有接上"谁来读、读完谁作废缓存、界面怎么刷新"** | **Bug-007**（标定取数漏传 `model_id` + 能力快照从不作废 + 前端只投递不跟结果） |
| 环境问题 | 依赖、运行时、平台差异 | CUDA 13 DLL 布局、ncnn 兼容性 |

## 3. 关系类型

| 关系 | 含义 |
|---|---|
| `similar-to` | 现象或根因高度相似，可横向参考 |
| `recurrence-of` | 同一问题再次出现 |
| `caused-by` | 当前问题由另一问题直接引发 |
| `affects` | 当前问题影响到其他模块或阶段 |

## 4. 沉淀的排查纪律

1. **区分「本轮回归」与「既有问题」**：拿不准时 `git stash push -- <改动路径>` 回基线复跑，
   基线同样失败即既有问题。**不要**因为它出现在自己的回归里就去改业务代码。
2. **断言要匹配产品约束，不要匹配具体措辞**。改文案必然连带改测试，是设计缺陷而非巧合。
   判据应写成「用户能看到什么」，如「说清训练权重 + 需转 ONNX」而非「包含『离线转换』」。
3. **脚本要自建环境**。需要独占资源（端口、库、数据根）时用内核分配（`bind(0)`），
   不要写死固定值 —— 写死值会让「资源被占」退化成「静默测了个别的东西」。
4. **`[PASS]` 与后续结果矛盾时，先怀疑自己的测量对象**，而不是产品逻辑。
5. **失败信息要能自诊断**：集合比对输出**对称差**（缺/多），不要只 dump 实际值。
6. 🔑 **同一缺陷模式要 grep 全仓，修一处不够**。Bug-002 最初只记「t704/t705 两处」，
   实际有**四处**（含 t704 自己第 6 段的第二处选型、整个 t706）。
   **只修一处 = 补丁式修复**，会留下继续红的地方。记录 Bug 时就要问「还有哪里是同一模式」。
7. 🔑 **同一口径要在全仓统一，别只改一处**。Bug-005：豁免口径本文件末尾与
   `run_t706_acceptance.cjs` 都有，唯独第 7 节漏改 → 环境一脏就误红。
   修法是抽出共享判据函数，三处复用，而不是再写一遍过滤条件。
8. **不要用全局计数做局部断言**。局部窗口的断言必须先滤掉与该窗口无关的背景噪声
   （Bug-005 即此），否则 `data/` 越脏越容易误报。
9. 🔑 **凡是「按文件名 / stem / 路径反查」的地方，都要问一句「这个名字会不会被改写」**。
   本项目已两次栽在同一族：T-719 复盘（产物不能预放到 `imported/<name>`，否则
   `_find_existing` 的定名约定失配）与 **Bug-006**（`save_import` 撞名改成 `X_1`，
   三处 stem 精确反查同时静默失配 —— 不抛错、只是判成「没下过」，**比崩溃更难发现**）。
   处置口径：**写入侧改名的规则要能被读取侧复用**（本轮：`normalized_stems()` 枚举等价形态），
   而不是在每处各写一遍匹配。⚠️ 枚举时**不要**无条件剥 `_\d+` —— 合法名也可能这样结尾
   （`2x_Ani4K_Compact_35000`），必须拿**已知来源名**去命中，做不到就不能剥。
11. 🔑 **验收要验「落在哪里」，不只要验「做了什么」**（Bug-008）。
    `F-03` 的 8 条浏览器用例在**任务中心**全绿（三模式切换、镜心跟指针、0 次图片请求），
    可 `PRD §6.1-4` 与 5A 定稿要求的是**工作台中栏**自动切入 —— **行为对、位置错**，
    于是偏差一路静默通过验收。**纪律**：凡 5A 定稿写了具体承载区（如 `CenterPanel`、
    「P1 预览工具条」「P2 表格」）的用例，除了断言行为，必须加一条**「元素在该区域内」**的
    选择器约束（例如断言容器作用域 `.wb-preview .cmp` 而不是裸 `.cmp`）。
    另注：**产品行为按需求变更后，断言要同步重写成「产品约束口径」而不是放宽** ——
    本轮的 E2E 第 3 节即从「完成后是单张源图」改为「完成后就地出现对比画布且两侧真实解码」。
10. 🔑 **「异步作业 + 进程内缓存」= 必须显式设计三步：谁写、谁作废、谁重新拉取**（Bug-007）。
    缺任何一步，界面就会永远停在旧结论，且**看代码像是对的**：
    - **谁写**：标定/EP 验证产出并落库（T-805 做了）；
    - **谁作废**：写入方落库后必须作废下游进程内缓存
      （`invalidate_capability_snapshot()`；`engine/capabilities.py` 的注释早就写了"需 refresh 重建"，
      但**注释不是接线**）；
    - **谁重新拉取**：前端不能"只投递 POST 就结束"，必须轮询到终态并刷新快照。
    ⚠️ 写断言时优先验**判据来源**（如「纯指纹口径取不到该模型记录 = 缺陷原形」），
    而不是只验最终文案 —— 否则修好一处仍可能被另一处缓存盖住。
