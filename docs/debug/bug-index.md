## 快速定位提示

- **回归跑出一片红，但不确定是不是本次改动引入的** →
  `git stash push -- server/ scripts/` 回基线复跑；**基线同样失败 = 既有问题**，不算回归。
  （本轮据此确认 Bug-002 与改动无关。）
- **`[PASS]` 与后续 `[FAIL]` 自相矛盾**（如"启动成功"却"数据库未创建"）→ 优先查 **Bug-003** 这类
  「测的环境不是它自己」的问题，而不是产品逻辑。
- **文案类断言频繁因措辞改动而红** → 断言应匹配**产品约束**（用户能看到什么），
  不要匹配具体措辞；否则每次改文案都要连带改测试（见 Bug-001 / Bug-004 的修法）。
- **同一缺陷模式散落多处** → 修第一处时**必须 grep 全仓同类代码**：
  Bug-002 最初记录为「t704/t705 两处」，实际有**四处**（含 t704 自身第 6 段与整个 t706）。
  只修一处属补丁式修复，会留下继续红的地方。
- **模型库补了多倍率后**，任何「按 `min_vram_mb` 排序取首个」的脚本都要复核
  （见 Bug-002）。
- **「明明做了却显示没做」（已下载仍显示可下载 / 已转换仍提示待转换 / 简介退化成兜底文案）**
  → 优先查**反查是否被改名打断**（见 Bug-006）：`save_import` 撞名会把 `X.pth` 改成
  `X_1.pth`（防覆盖），此后任何按**文件名 stem 精确比对**的反查都会**静默失配**。
  修法用 `model_registry.normalized_stems()`，**别写无条件 `re.sub(r"_\d+$", …)`**——
  目录里合法名 `2x_Ani4K_Compact_35000` 本来就以 `_35000` 结尾，盲剥会把合法名削掉。
- **「本机已标定，界面却说用的是保守参数」/「点了按钮没反应」**（见 Bug-007）→ 查三步：
  ① 消费侧取数是否**漏传 model_id**（`read_calibration_view(fp, None)` 只认通用记录）；
  ② 进程内快照（EP 验证 / 能力）是否在标定落库后**忘了作废**（缓存会一直返回启动时结论）；
  ③ 前端是否**只投递异步作业、不轮询终态、不刷新快照**（用户视角＝按钮坏了）。
  通用判据：**异步作业 + 进程内缓存 = 必须显式"作废 + 重新拉取"，否则界面永远停在旧结论。**
