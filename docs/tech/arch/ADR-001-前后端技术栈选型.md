# ADR-001 · 前后端分离技术栈选型

- **编号**：ADR-001
- **状态**：✅ 已接受
- **日期**：2026-09-30
- **相关**：PRD §2.1 业务模块划分、`dev-info.md` §1

## 背景

本项目是图像超分与修复的 Web 应用，需要一套前端界面 + 一个能调用 GPU/CPU 推理的后端服务。推理侧已有大量经过实测验证的既有资产：三个隔离 Python 环境（`.venvs/sr-gpu`、`sr-ov`、`sr-ovep`）、ORT 与 OpenVINO 的 EP 验证方法、首启自标定设计（详见 `docs/tech/research/`）。

## 决策

| 层 | 选择 |
|---|---|
| 前端 | **Vue 3 + Vite + TypeScript** |
| 后端 | **FastAPI（Python）** |
| 前端包管理器 | **npm**（随 nvm4w 全局 Node v24.15.0） |
| 后端包管理器 | **uv** |

**后端必须是 Python，这是硬约束，不是偏好**：推理栈 ONNX Runtime 与 OpenVINO 都是 Python 优先，且前面所有实测（EP 真实性验证、tile×精度矩阵、显存采样、自标定）都以 Python 脚本形式沉淀。换成 Node/Go 后端意味着要么放弃这些资产，要么额外维护一层跨语言通信，且**显存采样、EP profile 解析、DLL 路径注册这些机制无法在别的语言里等价复现**。

## 后果

**正面**
- 推理能力零损耗复用，自标定与降级链可直接移植为后端模块
- Python 的 `pynvml` / `psutil` / `onnx` / `openvino` 生态是这类应用的唯一现实选择
- FastAPI 原生 `async` + SSE 支持，与异步任务 + 进度推送的需求（ADR-005）天然契合
- Vue3 + Vite 启动快、体积小，适合工具型界面

**负面 / 代价**
- 开发期需同时跑前端 dev server 与后端进程（已用 Vite proxy 消除 CORS）
- 两个包管理器（npm + uv）与两套依赖树
- 前端无法直接复用后端类型定义，需要在契约层手工对齐（步骤 5B 冻结契约）

## 替代方案

| 方案 | 为何未采用 |
|---|---|
| Next.js / Nuxt 一体化全栈 | 其服务端能力是 Node，仍需外挂 Python 推理服务，反而多一层；且用户已定"前后端分离" |
| React + Vite + TS | 同为可行选项，用户选 Vue3；本决策不影响架构，替换成本限于前端目录 |
| Django | 自带 ORM/Admin 对本项目属过重；SSE 与异步任务支持不如 FastAPI 直接 |
| Flask | 异步与 SSE 支持需要额外扩展，长任务场景不占优 |
| Python 后端 + 前端直接调 Python | 需要浏览器端 Python（Pyodide），性能与依赖都不可行 |
