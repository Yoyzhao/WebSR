## 3. 大致功能点

| 模块 | 功能点 |
|---|---|
| **M1 任务中心** | 提交 / 排队 / 实时进度（SSE）/ 协作式取消 / 历史 / 产物 / 页面刷新不丢 / 启动回收"运行中" |
| **M2 推理引擎** | 能力探测 → **EP 真实性验证** → 首启自标定 → 决策 Profile → 水位反馈与降级；**保底档**兜住冷启动；档位模拟开关 |
| **M3 模型库** | 4 种格式路由（`.onnx` / `.bin` / `.pth` / `.safetensors`）、`.bin` 配套文件校验、sha256、元信息（含**最低显存需求**）、导入导出、离线转换入口 |
| **M4 图像处理** | BGR 与归一化、尺寸约束、分块、**overlap + feather 拼接（质量红线）**、后处理、格式转换 |
| **M5 媒体管理** | 上传扩展名白名单 + **服务端二次校验真实格式**、原图 / 结果 / 缩略图存储、检索、清理 |
| **M6 参数预设** | 保存 / 加载 / 删除 / 内置预设，**可绑定档位** |
| **M7 系统配置** | 数据根路径、并发上限、日志级别、保留策略、**标定状态与硬件信息展示**、诊断 JSON 导出 |
| **M8 微调支持** | 数据集打包导出（HR→自动配 LR）、训练脚本模板、产物回灌。**应用内不承载训练**（F-13 离线形态） |
| **档位与能力（P3）** | 档位模拟开关、能力声明（`supports_*`）、UI 按档位置灰、G-01~G-06、扩散池预留 |

## 4. 执行原则（源自已验收文档，本文件不新增规则）

1. **阶段门控**：每个阶段 / 切片完成后**必须用户验收**，通过才能进入下游。
2. **串行优先**：分离式项目按 `5A → 5B → 5C → 5D → 6 → 7` 推进；**5C 验收通过后 5D 才启动**。
3. **S1 优先**：所有 P1 / P3 工作排在 S1 完整走通之后。
4. **契约先行（口径已修正 2026-10-08）**：`api-contract.md` **草案**自 5C 起即为共同输入 —— 5C 据此产出 Mock 层与 TS 类型，5D 据此实现并**导出 OpenAPI schema**；契约的**最终冻结**须在**步骤 6 之前**完成（任务 **`T-700`**）。
   > 原表述「5B 冻结 API 契约前，禁止把任务下发给 5C / 5D」**作废**。原因：该文件 §7 的 7 个冻结点中有 **4 项**（分页筛选全量取值、SSE 心跳与重连退避、`resolved.reasons` 文案规范、类型生成方案）的取值**只能由后端与引擎产出**，前置在结构上不可能实现；强行前置只会得到凭猜测填满的契约，与「机制硬编码、数值运行时求」冲突。
5. **权威文档**：硬性约束见 [`docs/rules/project-rules.md`](../rules/project-rules.md)；架构与机制见 [`docs/tech/tech-arch.md`](../tech/tech-arch.md)；环境事实见 [`docs/tech/dev-info.md`](../tech/dev-info.md)。
