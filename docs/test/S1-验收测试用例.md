## 0. 编制口径

1. **用例来源**：每条用例都**可追溯到 PRD §2.5 的原文表述**（列在「PRD 原文」列）；量化阈值
   （≤1 s / ≤2 s / 误差 0 / <5%）**一律照抄 PRD**，不自拟、不放宽。
2. **用例编号**：`TC-S1-<序号>`，全局唯一（`project-rules.md` §4 的 `TC-<模块>-XXX` 规范，模块取 `S1`）。
3. **判定层**：
   - **HTTP** = 纯接口 + 产物文件可判定，无人参与；
   - **UI** = 必须在真实浏览器里判定（DOM 渲染 / 真实解码 / 页面刷新 / 鼠标键盘），HTTP 层**不可替代**；
   - **OPS** = 需要进程级操作（重启后端）。
4. **判定优先用相对/自指判据**（`T-703` 教训）：绝对阈值会随图像内容漂移，容易变成"调参调到绿"。
5. **NG（不通过）与 NT（不具备判定条件）严格区分**：`NG` = 功能不满足验收标准（缺陷）；
   `NT` = 环境/资产不足导致**无法判定**（须写明缺什么）。**不得用"相关脚本已全绿"顶替判定**。
6. **前置**：后端 `127.0.0.1:8000`、前端 `127.0.0.1:5173` 均在运行；`data/models/` 内有可用模型。

## 3. `F-02` 参数配置

> **PRD 原文**：页面上改动任一参数后执行，结果确实随参数变化（如 2x 与 4x 的输出尺寸不同）；
> "自动"档能正确落到引擎决策值并在界面显示该值

| 用例 ID | 步骤 | 预期结果 | 判定层 |
|---|---|---|---|
| `TC-S1-010` | `auto=true` 提交，任务完成后读 `resolved` | `resolved.tile` / `precision` / `backend` **均非 null**（引擎确实落了决策值）；`params.tile = null`（请求值保持"自动"） | HTTP |
| `TC-S1-011` | 打开任务详情抽屉，查看「参数与解析」区段 | 界面**渲染出**请求值 → 引擎解析值的对照（`resolved` 可见，含 tile / precision / backend） | UI |
| `TC-S1-012` | 切换模型（`mdl_1` → 另一可用模型），同图同参数各跑一次 | **两次产物不同**（像素级差异显著 > 噪声），且尺寸均正确 → "结果确实随参数变化" | HTTP |
| `TC-S1-013` | `auto=true` vs `auto=false, tile=<显式值>`，同图各跑一次 | `resolved.tile` **确实不同**（显式值被采纳）；两次均 `completed` | HTTP |
| `TC-S1-014` | 提交**模型倍数不支持**的 `scale`（内置模型均为 ×4，请求 `scale=2`） | **明确拒绝**：`4xx` + 结构化错误体（`code` / `message` / `suggestion` 三要素齐全），文案指出"该模型为 ×4"，**不得**接受后跑到中途报通用 `INTERNAL_ERROR` | HTTP |
| `TC-S1-015` | 界面选择倍率控件，查看可选值 | 倍率选项**受所选模型约束**（模型为 ×4 时仅 ×4 可选，其余置灰并给出原因） | UI |

> **`F-02` 的口径说明**：PRD 举例「2x 与 4x 的输出尺寸不同」。当前 `data/models/` 内**全部内置模型均为
> ×4**（`builtin_catalog.py` 五条 `scale=4`），**没有任何 ×2/×3 权重** → 该示例在当前资产下
> **无法演示**。因此本组用例改以「模型切换 / tile 改动」证明"结果随参数变化"，
> 并把「不可用的倍数被明确拒绝」立为独立用例（`TC-S1-014`/`TC-S1-015`）。
> ×2/×3 的真实演示**需先导入一个 ×2 模型**（导入通道见 `F-05`）——属**资产缺口**，记在报告。

## 7. `F-06` 硬件能力面板

> **PRD 原文**：面板显示的可用显存与实际相差 < 5%；**展示的执行提供器必须有 profile 节点归属作为证据**
> （这是防静默回退的唯一手段）
> **硬约束依据**：`project-rules.md` §2.2 铁律 2 —— 「禁止用 `session.get_providers()` 当作 EP 生效的证据」。

| 用例 ID | 步骤 | 预期结果 | 判定层 |
|---|---|---|---|
| `TC-S1-050` | 读 `GET /api/system/capabilities` 的 `device_facts.available_vram_gb`；同时用 **`nvidia-smi`** 独立读取显存（`total - used`） | 两者**相差 < 5%**（两个来源在同一时间窗内取值） | HTTP + OPS |
| `TC-S1-051` | 检查 `device_facts` 是否"实读"而非标称 | 同时返回 `nominal_vram_gb` 与 `available_vram_gb`，且**前者 > 后者**（桌面进程占用可见）；`available < nominal` 是"真实读"的直接证据 | HTTP |
| `TC-S1-052` | 检查 `ep_evidence` 每一条 | 每条含 **`node_count` + `cpu_node_count` + `provider`**（节点归属证据），**不得**只有 provider 名 | HTTP |
| `TC-S1-053` | 对照 `active_backend` 与其证据条目 | 生效后端的那条 EP 证据 `verified=true` **且** `cpu_node_count = 0`（"CPU 节点数 = 0"才是真接管；节点数 = 1 是整图融合的正常现象） | HTTP |
| `TC-S1-054` | 打开硬件能力页，查看显存卡片 | 界面显示的数值与接口一致，且**标注为「实读」**（区分标称与可用） | UI |

> **`< 5%` 的对账口径**：`nvidia-smi` 与 NVML 读的是同一物理量，但**取值时刻不同**（脚本先取接口、
> 再取 `nvidia-smi`）。若机器处于空闲态，两者差异通常在 1% 以内；若期间有推理在跑，差异会放大 ——
> 故本用例**在无任务运行时执行**，并记录两次取值的实际时刻间隔。
