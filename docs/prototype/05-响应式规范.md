## 1. 断点

| 档位 | 范围 | 主工作台布局 | 独立页布局 |
|---|---|---|---|
| **宽屏** | **≥ 1440px** | **三栏**：左 320 ｜ 中 fill ｜ 右 340 | 单栏，**内容有宽度上限**（见 §2） |
| **中屏** | **1024 – 1439px** | **两栏**：左 300 ｜ 中 fill；**参数面板折叠为抽屉** | 单栏，容器撑满 |
| **窄屏** | **< 1024px** | **单栏堆叠**：预览优先，其余下沉 | 单栏，容器撑满 + 组件降级 |

**兜底下限**：1280 × 720 及以上必须正常可用（PRD §3.3）。低于此分辨率不做保证。

## 2. 宽屏（≥ 1440）与内容宽度上限

主工作台即设计稿 P1 / P6 的形态，三栏同时可见，参数改动与预览结果无需切换即可对照。

### 2.1 独立页必须有内容宽度上限

**没有上限会出什么问题**：设置类页面的行采用两端对齐（label 左、值右）。容器越宽，label 与它的值离得越远，**视觉分组断裂**——用户需要横跨屏幕才能完成对应。

以 P5「模型目录」一行为例，实测容器宽度与行内留白的关系：

| 窗口宽 | 容器宽 | 行内留白 | 观感 |
|---|---|---|---|
| 1440（未加上限时） | 1376 | **1085px** | ❌ label 与值完全脱离 |
| 1920（未加上限时） | 1856 | **1565px** | ❌ 更糟 |
| 1344（统一上限，单列不处理） | 1288 | **约 997px** | ❌ 仍脱离 —— **收窄容器本身并不解决分组问题** |
| **1344（统一上限 + 双列）** | 每列约 630 | **约 300px** | ✅ 仍是一个视觉组 |

> **结论（2026-10-08 修正）**：单纯收窄容器（旧方案的 880）能缓解分组问题，
> 但代价是四页宽度不一致。真正的解法是**同时**约束「容器宽度」与「行内分组」：
> 统一 1344 后，P5 改为双列（每列约 630px）、P4 的宽卡体改为「固定 label 列 + 值左对齐」。
> 这样既保证四页边界一致，又保证 label 与值始终成组。

### 2.2 各页上限（**统一值 1344**）

> **2026-10-08 由「逐页差异化」改为统一值。**
> 原本四页各不相同（1344 / 1408 / 1200 / 880），理由是「按内容类型推导」；
> 但实际使用中发现**切换页面时内容区左右边界跳变，观感割裂**，故统一。

| 页面 | 类型 | max-width | 说明 |
|---|---|---|---|
| **P1 / P6 主工作台** | 三栏工作台 | **不限制** | 中栏是图像预览区，宽度直接转化为可用预览面积，越宽越好 |
| **P2 任务中心** | 数据表格 | **1344** | 6 个固定列合计 974px，文件列约 370px，与实际文件名长度匹配 |
| **P3 模型库** | 卡片网格 | **1344** | 3 列各约 419px，（1344 − 56 padding − 32 gap）÷ 3，卡片仍舒适 |
| **P4 硬件能力** | 展示 + 证据表 | **1344** | 原 1200；统一后证据表更宽裕，4 列不拥挤 |
| **P5 系统配置** | 设置表单 | **1344** | 原 880；**改为双列网格**，每列约 630px，label 与值保持成组 |

**取值 1344 的依据**

1. 模型库是唯一有硬性列宽要求的页面（卡片 ≥ 400px 才舒适）：1344 下 3 列各约 419px；
2. 任务中心原本就是 1344，其表格列宽经过推导，沿用不引入回归；
3. 1440px 基准稿下 1344 居中，左右各留 48px，接近撑满；
4. 1920px 及以上仍为 1344 居中，卡片不会过度拉伸。

**超出上限时内容居中**（左右留白对称），而不是左对齐后把空白全堆在右侧。

```css
/* 独立页内容容器 */
.page-content {
  max-width: var(--page-max-width); /* 统一 1344 */
  margin-inline: auto;
  padding-inline: 32px;
}
```

**统一宽度带来的两处连带调整**（不处理会产生新问题）

| 位置 | 原问题 | 处理 |
|---|---|---|
| **P5 系统配置** | 容器由 880 放宽到 1344 后，若仍单列，`SettingsRow` 的「label 左 / 值右」两端对齐会让二者相隔近 900px | 改为 **grid 双列**（每列约 630px），label 与值始终成组 |
| **P4 硬件能力** | 卡片是全宽单列（约 1288px），同样会让 label 与值脱离 | `SettingsRow` 增加**容器查询**：卡体 ≥ 1000px 时自动改为「固定 220px label 列 + 值左对齐」 |

> **容器查询阈值 1000px 的选取**：compact 档（<1024 视口）的卡体不足 968px，
> 因此不会误触发，也就不会与「窄屏上下堆叠」规则争抢布局。
> 窄卡体（工作台右栏约 300px、设置页双列约 630px）保持原有两端对齐。

> ⚠️ **CSS 书写顺序约束（易踩）**：`@container` 覆盖块**必须置于样式表末尾**。
> 它要覆盖 `.settings-row` 与 `.settings-row__value` 的基础声明，而两者特异性相同
> （0,1,0），胜负由书写顺序决定。若误置于基础声明之前，会出现
> **「明明变成了网格、值却仍贴在右侧」**的现象 —— 5C 修复时实际踩到过。

> **历史推导（已作废，仅存档）**：P2 曾取 1344（修正自 1600）、P3 曾取 1408
> （修正自 1904）、P4 曾取 1200、P5 曾取 880。P2/P3 两次修正的原始推导见
> `README.md` §7 审查记录第 3、4 条 —— **修正原则仍然成立**：
> 内容宽度上限应由**内容的自然宽度**推导，而不是由「能塞下几列」推导。
> 统一为 1344 后，该原则体现为「取四页约束中最紧的那个」。

## 3. 中屏（1024 – 1439）

### 3.1 主工作台

| 区域 | 变化 |
|---|---|
| 左栏 | 320 → **300** |
| 中栏 | 保持 flex，两侧自动收窄 |
| 右栏 | **移出流式布局，改为 `el-drawer`**（从右侧滑出，宽 340） |
| 入口 | PreviewToolbar 右侧新增「参数」按钮（图标 + 文字），点击打开抽屉 |
| 参数变更提示 | 抽屉入口按钮上加 `warning` 角标——**面板折叠后提示不能丢**，否则用户改了参数却看不到"需重新执行" |
| 执行按钮 | 抽屉内底部固定（与宽屏一致的位置关系） |

**为什么把参数面板而不是任务列表折进抽屉**：任务列表是**进度监控**对象，推理需数分钟，用户会频繁回看；参数面板是**一次性设置**对象，设完就不再看。把低频的收起来。

### 3.2 独立页

| 页面 | 变化 |
|---|---|
| P2 任务中心 | 容器撑满；表格**隐藏「放大」「产出」两列**，两项合并进「文件」列的副行（见 §5） |
| P3 模型库 | 容器撑满；卡片仍 448px，**自动降为 2 列**（放不下 3 列） |
| P4 硬件能力 | 容器撑满；双列卡**保持两列**（各约 480px，仍可读）；宽卡体的 `SettingsRow` 维持左对齐网格（卡体仍 ≥ 1000px） |
| P5 系统配置 | 容器撑满；**双列退回单列**（< 1280 视口），表单恢复单栏自上而下的阅读顺序 |

## 4. 窄屏（< 1024）

### 4.1 主工作台

单栏堆叠，顺序按任务流：

```
┌─────────────────────────┐
│ TopBar（导航折叠为汉堡菜单）│
├─────────────────────────┤
│ 预览区（优先，置顶）      │
│  对比画布 + 模式切换      │
├─────────────────────────┤
│ 执行区（吸底）           │
│  「开始超分」+ 参数摘要   │
├─────────────────────────┤
│ 参数面板（可折叠区块）    │
├─────────────────────────┤
│ 上传区                  │
├─────────────────────────┤
│ 任务列表                │
└─────────────────────────┘
```

| 项 | 处理 |
|---|---|
| 顶栏导航 | 5 个 Tab 折叠进汉堡菜单（`el-drawer` 左侧滑出）；档位徽标与 EP 徽标保留在顶栏（它们是状态，不是导航） |
| 对比画布 | 宽度撑满，高度按 16:9 计算；**不做横向滚动** |
| 参数面板 | 变为可折叠区块，默认折叠；折叠时显示当前参数摘要（如「4× · RealESRGAN_x4plus · 自动」） |
| 执行按钮 | `position: sticky` **吸底**，保证任何时候都能提交 |
| 任务中心表格 | 见 §5 |

**关键约束**：即使窄屏，**「开始超分」与进度反馈也不得被移到二级页面**——它们是主任务的起点与终点。

### 4.2 独立页

| 页面 | 变化 |
|---|---|
| P2 任务中心 | 表格 → **卡片列表**（见 §5）；筛选 chips 由单行改为**可换行**（不做横向滚动） |
| P3 模型库 | **2 列**（768–1023px）；**< 768px → 1 列**。页头的「导入模型」按钮保持可见，不收入溢出菜单 |
| P4 硬件能力 | 双列卡 → **单列堆叠**；**证据表改为卡片式**——每个后端一张小卡（后端名 + 节点归属 + CPU 节点数 + 判定成对呈现），不再用 4 列表格 |
| P5 系统配置 | **行由两端对齐改为上下堆叠**：label 在上、控件在下，控件宽 100%。窄屏下两端对齐会让 label 与值分居屏幕两侧，必须改堆叠 |

> **P4 证据表为何不保留表格形态**：该表的列宽需求（后端 260 + 节点归属 + CPU 节点数 150 + 判定 180）在 768px 下会挤到无法阅读，而横向滚动会破坏"列头与内容对齐"。改成卡片式是唯一不损失信息的降级路径。

## 5. 表格的小屏降级（任务中心）

| 断点 | 处理 |
|---|---|
| ≥ 1440 | 完整 7 列（见 `01` §4） |
| 1024 – 1439 | 隐藏「放大」「产出」两列；这两项合并进「文件」列的副行（小字 `4× · 7680 × 4320`）。**信息不丢，只是换位置** |
| < 1024 | 表格 → **卡片列表**。每张卡片：状态 + 文件名 + 关键参数两行 + 操作按钮组 |

**禁止**：在小屏上给表格加横向滚动。横向滚动会同时破坏"列头与内容对齐"和"操作按钮位置稳定"两个约束。

## 6. 触摸与指针

| 项 | 要求 |
|---|---|
| 触摸目标 | ≥ 44×44（窄屏）／ ≥ 32×32（桌面图标按钮） |
| 对比滑块把手 | 窄屏下从 24 放大到 **32**，并扩大不可见的触摸热区 |
| 拖拽上传 | 移动端保留（`el-upload` 的 drag 在触摸设备上降级为点击选择，需确保点击态仍可触发） |
| 悬停态 | 所有悬停效果（`bg-hover`）都必须有一个**非悬停的等价态**（选中/激活），否则触摸设备上无法感知 |

## 7. 断点的实现方式

```ts
// 统一断点与页面宽度常量，禁止在组件里散落魔法数字
export const BREAKPOINTS = {
  compact: 1024,   // < 此值：单栏 + 组件降级
  medium: 1440,    // < 此值：两栏 + 抽屉
  // ≥ medium：三栏
} as const

// 2026-10-08 由逐页差异化统一为单一值
export const PAGE_MAX_WIDTH_VALUE = 1344

export const PAGE_MAX_WIDTH = {
  tasks: PAGE_MAX_WIDTH_VALUE,     // P2 任务中心
  models: PAGE_MAX_WIDTH_VALUE,    // P3 模型库（3 列各约 419px）
  hardware: PAGE_MAX_WIDTH_VALUE,  // P4 硬件能力
  settings: PAGE_MAX_WIDTH_VALUE,  // P5 系统配置（内部双列，每列约 630px）
  // 主工作台不设上限：中栏是图像预览区
} as const
```

- 用 `window.matchMedia` 或 CSS 媒体查询均可，但**断点判定与页面宽度必须集中在单一入口**，禁止各组件自行判断。
- **Vite `server.strictPort: true`**：端口冲突时必须报错停止，**禁止自动从 5173 切到 5174**（`project-rules` §2.4 与 SKILL.md 强制原则第 8 条）。

## 8. 本阶段未做的事（明确留白）

| 项 | 原因 |
|---|---|
| 移动端（< 768px）的完整设计稿 | PRD §3.3 只要求 1280×720 及以上；本机单机自用场景不考虑手机操作。§4 的单栏堆叠规则是**兜底**，不是优化目标 |
| 平板横竖屏切换的专门适配 | 同上 |
| 超宽屏（≥ 2560）的专门设计 | §2 的宽度上限已覆盖该场景（内容居中），无需为超宽屏单独设计 |
| 打印样式 | 不适用 |

> 这些约束如果后续要放开（例如改为局域网可访问，PRD §3.2 提到需先补鉴权），需要回到步骤 5A 补设计，而不是在实现阶段临时加媒体查询。
