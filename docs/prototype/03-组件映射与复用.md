# 03 · 组件映射与复用策略

> 步骤 5A 产出 ｜ UI 组件库：**Element Plus 2.14.6**（T-302 定案）｜ 最后更新：2026-09-30

---

## 1. 原则

1. **先查再建**：实现任何区块前，先确认是否已有可复用的业务组件或 Element Plus 组件；确认不存在才新增。
2. **同类只写一次**：相同业务语义的结构（key-value 行、状态文字、操作按钮组、页面头）必须收敛为统一封装。
3. **不重新发明 UI**：布局骨架、间距、圆角、颜色一律取自 5A 产出，不在编码阶段另行决定。

## 3. Element Plus 组件映射

| 界面区块 | Element Plus | 定制要求 |
|---|---|---|
| 主导航 Tab | `el-tabs`（或按设计稿自绘 flex Tab） | 设计稿是扁平方形 Tab（4 圆角、无下划线）。若用 `el-tabs` 需关闭默认下划线并覆盖高度；自绘更省事，**二者取一，不得混用** |
| 上传区 | `el-upload` + `drag` | 必须替换默认拖拽区样式，改为设计稿的 `border-strong` 描边 + 居中图标布局 |
| 参数：放大倍数 | `el-radio-group` + `el-radio-button` | 需覆盖为等分等宽（`fill_container`），默认是按内容宽度 |
| 参数：模型选择 | `el-select` | 选项需禁用不可用模型（`disabled` + 后缀原因） |
| 参数：自动档开关 | `el-switch` | — |
| 对比视图 | **自定义** `CompareSlider` | ⚠️ **不能用 `el-slider`**：`el-slider` 是数值输入控件，无法表达"分割图像"的语义 |
| 进度条 | `el-progress` | `:show-text="false"`、`:stroke-width="4"`、`:show-text` 关闭后在外部放阶段文案 |
| 任务表格 | `el-table` | 列宽按 `01` §4 的定义；`header-cell-style` 设 `bg-elevated`；**关闭纵向边框线** |
| 分页 | `el-pagination` | 需改为设计稿的「文字汇总 + 上一页/下一页」精简形态 |
| 状态筛选 | `el-check-tag` 或自绘 chip | 设计稿为胶囊 chip，含数量角标 |
| 搜索框 | `el-input` + `prefix-icon` | 宽度 220 固定 |
| 按钮 | `el-button` | `type="primary"` 主操作；`default` 次级；`link`/`text` 用于删除行内操作 |
| 徽标 | `el-tag` | 需尺寸定制（11px 字 + 8/3 内边距）；格式徽标 `size="small"` 仍偏大 |
| 提示条 | `el-alert` | 保底档提示、条件支持提示；需关闭 `closable`（这些提示是持续状态，不该被关掉） |
| 抽屉 | `el-drawer` | 参数面板窄屏折叠（见 `05`）；**任务详情抽屉**（见 `04` §3） |
| 反馈消息 | `el-message` | 操作成功/失败提示 |
| 确认框 | `el-message-box` | 删除模型、清空已完成任务、清理中间产物 |
| **弹窗** | **`el-dialog`** | **模型导入两级弹窗**（见 `01` §5.1） |
| **标签页** | **`el-tabs`** | **任务详情抽屉的区段切换**（宽屏）；窄屏改为纵向堆叠。若与主导航的 Tab 样式冲突，抽屉内改用 `el-segmented` |
| 卡片 | `el-card` | 或直接用带描边的 `div`（设计稿卡片样式简单，`el-card` 的默认内边距与阴影需全部覆盖——**若覆盖成本高于自绘，直接自绘**） |
| 描述列表 | `el-descriptions` | P4 硬件事实 / P5 配置行；需改为 `SPACE_BETWEEN` 两端对齐而非表格式 |
| 空态 | `el-empty` | 必须替换默认插图，用设计稿的线性图标 |
| 骨架屏 | `el-skeleton` | 模型列表首次加载（PRD §6.2） |

## 4. 样式 token 沉淀

**唯一来源**：[`tokens.css`](tokens.css)（从设计稿导出，含 `[data-theme="Light"]` 覆盖块）。

落地位置建议：`web/src/styles/tokens.css`，在 `main.ts` 中于 Element Plus 样式**之后**引入（保证可覆盖组件库变量）。

**命名**：可把 `--Theme-*` 重命名为 `--color-*`、`--Scale-*` 重命名为 `--space-*` / `--radius-*`，但**必须保持语义一一对应**，且重命名后 `tokens.css` 需同步更新（它是设计交付物，需与代码一致）。

## 5. 禁止事项（违反即返工）

| # | 禁止 | 原因 |
|---|---|---|
| 1 | 页面内硬编码色值（`#0F0E0E`、`rgb(...)`） | 硬编码元素不参与主题切换，浅色模式下会变成暗块 |
| 2 | 各页面各写一套按钮 / 状态标签 / 设置行的样式 | 同类组件漂移，后续无法统一改版 |
| 3 | 用原生 `input` / `select` / `button` 拼业务界面 | 与 Element Plus 的表单语义、焦点态、禁用态不一致 |
| 4 | `el-slider` 当作图像对比滑块 | 语义错误，无障碍与交互都会出问题 |
| 5 | 深色判断散落在各组件（`if (isDark)`） | 主题切换必然漏项，且无法支持"跟随系统" |
| 6 | 给常规卡片加阴影 | 深色界面上阴影不可见，只增加渲染成本 |
| 7 | 表格加纵向边框线与斑马纹 | 与"用留白而非分割线制造层次"冲突，且与设计稿不符 |

## 6. 组件状态覆盖要求

每个业务组件必须覆盖以下状态（PRD §6.2 / WebUI 原则 3）：

| 状态 | 表现 |
|---|---|
| `loading` | 骨架屏（列表）或进度条（任务）；**不用整页遮罩**，工具型界面要允许用户在等待时查看其他信息 |
| `empty` | 图标 + 主文案 + 说明（`EmptyState`） |
| `error` | 错误摘要 + 可展开的详情 + 一个明确的下一步动作（重试 / 降低倍数 / 查看日志） |
| **`interrupted`（已中断）** | **`warning` 色状态文字 + 原因「上次运行被异常终止」+「重试」主操作**（见 `04` §2.6）。**不是 `error`**——成因是外部因素而非推理失败 |
| `disabled` | `opacity: 0.55`（不可用卡片）/ `0.6`（禁用说明块）+ **文字写明原因** |
| `partial`（降级） | `warning` 色标注 + 具体降到什么值（如「已降档 tile 256」） |
| `reading/active` | `bg-hover` 底 + `text-primary`（用于选中态、悬停态） |
| **`unknown`（未知枚举兜底）** | **显示原始值 + `text-tertiary`**。后端新增状态时前端不得白屏或抛错 |

> **降级态是本项目特有的必需状态**：PRD §2.6 与 `project-rules` §2.4 都要求"降级必须显式，不得静默降画质"。任何组件只要可能处于降级路径上（任务卡、表格行、参数面板、硬件面板），就必须能表达"我降了，降成什么，为什么"。
